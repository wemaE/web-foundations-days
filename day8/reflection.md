# Course Reflection

Throughout the Web Foundations course, the most challenging concept for me was mastering asynchronous JavaScript and state management in Day 5. Moving beyond synchronous DOM manipulation to orchestrate `fetch` requests with `async/await`, handle loading and error states reliably, and prevent UI race conditions felt daunting at first. I overcame this by breaking network calls into clear lifecycle phases using `try/catch/finally` blocks, deliberately introducing mock network errors to test edge cases, and building modular helper functions to ensure button states and error messages reset predictably.

For my capstone project, the QuickNotes app, no formal external peer feedback document was recorded in the repository. However, based on my own user testing and self-evaluation, the biggest area for improvement is data persistence and synchronization. Currently, notes are stored exclusively in the browser's `localStorage`. This confines notes to a single device and risks data loss if the browser cache is cleared. Based on this self-assessment, I would improve the capstone by implementing a lightweight REST API backend with PostgreSQL to persist notes across devices, introducing user authentication, and allowing custom multi-tag filtering instead of hardcoded categories.

Next, I plan to dive deeper into full-stack development and backend engineering. Having designed database schemas in Day 6 and system architectures in Days 7 and 8, I want to learn Node.js and Express to build production-ready REST APIs. I also want to gain hands-on experience connecting backend services to PostgreSQL, managing database migrations, implementing JWT authentication, and deploying containerized services with Docker to the cloud.
